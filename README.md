# 🎤 唱歌音准实时监测（do re mi 调音器）

一个纯前端的网页版"音准检测 + 练习记录"工具，专门给我这种**记不住音名、只会唱 do re mi** 的人用。

对着麦克风唱，页面上直接显示：

- **📈 实时音高曲线**：一条跟着你音高实时滚动的线（可切 5/10/20 秒窗口），
  线落进**绿色带**就是准，黄 = 偏一点，红 = 偏很多；下面还有一条实时**声波**（波形）线
- 你现在唱的是 **do / re / mi / fa / sol / la / xi** 里的哪一个，以及是第几组（八度）
- 这个音的**标准频率**是多少 Hz，你唱的实际频率是多少 Hz
- 你**偏高 / 偏低多少音分**（100 音分 = 1 个半音），用指针表实时显示
- 完整音阶的**标准频率对照表**，点一下就能听标准音
- **我的音域**设置：选自己的声部（预设 男低音 / 男中音 / 男高音 / 女低音 / 女中音 / 女高音 / 自定义），
  音域外的音会自动**变灰**并提示，不会让你硬唱上不去的高音
- 可以**录音**（只记音高、不存声音），自动统计"每个音平均偏高多少、稳不稳"，并**导出 JSON** 发给我做分析

> 所有计算都在你自己的浏览器里完成，**声音不会上传到任何服务器**。

---

## 一、怎么用

1. 用 **Chrome / Edge / Safari** 打开网页（必须是 `https://` 或者 `localhost`，否则浏览器不给用麦克风）。
2. **先设音域**：右上角「我的音域」选自己的声部（我的选「男中音偏男高」，见第二节）。
   设好之后，音阶表里音域外的音会变灰，高音不再"骗"你去唱。
3. 点 **「开始收音」**，在弹窗里选"允许"。
4. 对着麦克风唱一个长音，比如 `la3——`，看两样东西：
   - **①下面的实时音高曲线**：线在绿色带里 = 准；往上飘 = 偏高。
   - **大字号唱名 + 指针**：指针在 **±25 音分**以内就是准的，往右 = 比标准音**高**。

### 针对"sol 容易太高、la 上不去"的练法

1. **把音区调到第 3 组**（do3 = 130.81 Hz，sol3 = 196.00，la3 = 220.00）。
   别再在 do4 起：do4–do5 那条音阶的 sol4 = 392、la4 = 440 已经顶到你的天花板了。
2. 在「标准频率表」里点 **▶ 听**，把 `sol3`、`la3` 的标准音各听 3 遍，先记住那个高度。
3. 慢慢唱 `sol3 → la3`，盯**实时曲线**：如果一到 sol 线就往上飘，说明你是**靠往上滑找音**，而不是直接落在音上。
4. 改成"先在心里想好高度，再出声"，出声后立刻看线有没有落进绿色带（±25 音分内）。
5. 反过来练：`do4 → xi3 → la3 → sol3`，从高往低唱比从低往高唱更容易找准，不容易越滑越高。
6. 用「单音跟唱测试」逐音测试，每个音重复 5 次，记录分数，看哪个音最难稳。

## 二、我的音域 = A2 ~ A4（110 ~ 440 Hz）

用音域测试测出来的是 **A2 到 A4，正好两个八度（24 个半音）**，属于**男中音偏男高音**那一类：

- 男中音（Baritone）常见音域约 **A2–F4**，男高音（Tenor）约 **C3–A4**；
  你下能到 A2、上能到 A4，是**偏低音区厚、但高音还能往上够**的类型 —— 典型的 Baritone with a lean toward Tenor。
- **关键结论**：`sol4 = 392 Hz` 已经贴着你 440 的天花板，`la4 = 440` 就是你极限。
  所以你原来按 do4 起的音阶往上唱，到 sol4/la4 当然"上不去"，那不是音准差，是**音阶起太高了**。
  练声改用 **do3 起**（do3 = 130.81 → do4 = 261.63），你的 sol3 = 196、la3 = 220 会轻松很多。

你的音域内每个音的频率：

| 唱名 | do | re | mi | fa | sol | la | xi |
|---|---|---|---|---|---|---|---|
| **第 2 组** | do2 65.41 ❌低于A2 | — | — | — | — | **la2 110.00** | xi2 123.47 |
| **第 3 组** | **do3 130.81** | re3 146.83 | mi3 164.81 | fa3 174.61 | **sol3 196.00** | **la3 220.00** | xi3 246.94 |
| **第 4 组** | do4 261.63 | re4 293.66 | mi4 329.63 | fa4 349.23 | sol4 392.00 | **la4 440.00** | xi4 493.88 ❌ |

（❌ = 超出你的音域。网页里的音阶表会自动把这些音标灰。）

以 **A4(la) = 440 Hz** 为准，十二平均律：

| 唱名 | 音名 | 频率 (Hz) |  | 唱名 | 音名 | 频率 (Hz) |
|---|---|---|---|---|---|---|
| do  | C4 | 261.63 | | sol | G4 | 392.00 |
| re  | D4 | 293.66 | | la  | A4 | 440.00 |
| mi  | E4 | 329.63 | | xi  | B4 | 493.88 |
| fa  | F4 | 349.23 | | do(高) | C5 | 523.25 |

其他八度：低一组（C3 ~ C4）是 `do=130.81, re=146.83, mi=164.81, fa=174.61, sol=196.00, la=220.00, xi=246.94`；
高一组（C5 ~ C6）是 `do=523.25, re=587.33, mi=659.26, fa=698.46, sol=783.99, la=880.00, xi=987.77`。
规律：**每升高一个八度，频率 ×2**；每升高一个半音，频率 ×2^(1/12)。

网页里的「标准音对照」可以切换组，直接看到任意八度的数字。

## 三、部署到 GitHub Pages（免费）

### 方法 A：网页操作（不用命令行）

1. 打开 <https://github.com/new>，新建一个仓库，例如 `vocal-pitch-monitor`，选 **Public**，点 Create。
2. 进入仓库 → **Add file → Upload files**，把本文件夹里的 **`index.html`、`style.css`、`js/` 文件夹**（`js/pitch.js`、`js/app.js`）拖进去，点 **Commit changes**。
3. 仓库 → **Settings → Pages**，`Source` 选 **Deploy from a branch**，`Branch` 选 **main** 和 **/ (root)**，点 Save。
4. 等 1 分钟左右，刷新页面，会看到网址：`https://你的用户名.github.io/vocal-pitch-monitor/`。
5. 用手机或电脑打开这个网址（**https**，可以用麦克风），加到主屏幕/书签即可。

### 方法 B：命令行

```bash
cd 本文件夹
git init
git add .
git commit -m "vocal pitch monitor"
git branch -M main
git remote add origin https://github.com/你的用户名/vocal-pitch-monitor.git
git push -u origin main
```

推送完同样在 **Settings → Pages** 里把 Branch 设为 `main` / `/ (root)` 就行。
（也可以在仓库里加一个 GitHub Action 用 `actions/deploy-pages` 部署，效果一样。）

### 本地测试

直接双击 `index.html` 大多数情况下能打开，但浏览器在 `file://` 下可能不给麦克风权限。更稳的做法是起个本地服务器：

```bash
cd 本文件夹
python -m http.server 8000
# 然后浏览器打开 http://localhost:8000
```

## 四、把录音发给我做分析

1. 点「开始收音」→ 点「⏺ 开始录音」。
2. 按顺序唱：`do re mi fa sol la xi do`，**每个音唱 2~3 秒长音**，一共 30 秒左右。想让我看你唱得高的那几个音，就把 `sol`、`la` 多唱两遍。
3. 点「⏹ 停止录音」，然后点 **「导出 JSON」**，浏览器会下载一个 `pitch-日期-时间.json`。
4. 把这个文件发给我就行。

JSON 文件长这样（已经带好了汇总统计，不用你自己算）：

```json
{
  "app": "vocal-pitch-monitor",
  "a4": 440,
  "durationMs": 31240,
  "summary": {
    "avgAbs": 22.4,          // 全程平均偏差（音分，绝对值）
    "avgBias": 8.1,          // 全程平均偏差（带符号，正数=整体偏高）
    "in25": 41.2,            // 有多少比例落在 ±25 音分内
    "in50": 78.6,            // 有多少比例落在 ±50 音分内
    "nearEdge": 12.0,        // 有多少比例卡在两个半音正中间
    "worst": { "sol": "sol", "avg": 46.3 }
  },
  "perNote": [               // 逐音统计：哪个音偏高、稳不稳，一眼就能看出来
    { "solfege": "sol", "note": "G4", "seconds": 3.1, "frames": 44,
      "avgCents": 46.3, "avgAbsCents": 46.3, "sdCents": 12.4,
      "in50Percent": 55.0, "in25Percent": 2.1 }
  ],
  "points": [                // 原始音高轨迹，每 ~70ms 一个点
    { "t": 0, "f": 392.51, "midi": 67.02, "cents": 2.1, "note": "G4", "solfege": "sol4" }
  ]
}
```

有 `perNote` 和原始 `points` 这两层数据，我可以：
- 指出你哪个音是**系统性偏高/偏低**（比如 sol 平均 +46 音分，那就是真高了快半个音）
- 看你是**起点不准**还是**唱着唱着飘走**（`points` 里的走势）
- 看**稳定性**（`sdCents` 大就是抖）
- 对比前后两次录音，看有没有进步

也可以导出 **CSV**，用 Excel 自己画图。

## 六、技术说明

- **音高检测**：YIN 算法（自相关 + 累积均值归一化 + 抛物线插值），在 48kHz 采样下用 4096 点窗口，
  检测范围约 `C2(65Hz) ~ E6(1300Hz)`。纯正弦波实测误差 < 0.4 音分，加噪声后 < 2 音分。
- **实时曲线**：约 30fps 重绘、16fps 做音高分析；纵轴自动跟你的音高走（平滑跟随，不抖），
  每条横线是一个半音并标了唱名，绿色带 = ±25 音分（准音区）。声波是最近约 85ms 的波形。
- **取值策略**：每 ~60ms 分析一次，取最近 400ms 内的有效检测结果做**中位数 + 邻近平均**，
  避免偶尔的八度跳变和抖动让显示乱跳。
- **音名换算**：`f = A4 × 2^((n − 69) / 12)`，`n` 是 MIDI 音号（中央 C = 60 = do4）。
  偏差用音分表示：`cents = (实际MIDI − 最近整数MIDI) × 100`。
- **隐私**：没有后端、没有第三方脚本 CDN、没有任何网络请求，麦克风数据只在本机内存里处理。
- **兼容性**：Chrome / Edge / Safari 最新版（需要 `getUserMedia` + `AudioContext`），
  手机端也能用（iOS Safari 需要 https）。

## 七、小提醒

- 唱的时候**别用抖音**，音高抖得厉害检测会跳来跳去。
- 环境和麦克风距离影响很大：安静房间 + 麦克风离嘴 15~25cm 最准。
- 用手机/电脑音箱播放参考音时，麦克风会把参考音也收进去，建议**戴耳机**。
- 一次只唱一个音，唱稳了再看指针，比一边滑一边看有用得多。
