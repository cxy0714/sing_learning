# 🎤 唱歌音准实时监测（do re mi 调音器）

一个纯前端的网页版"音准检测 + 练习记录"工具，专门给我这种**记不住音名、只会唱 do re mi** 的人用。

对着麦克风唱，页面上直接显示：

- **📈 实时音高曲线**：一条跟着你音高实时滚动的线（可切 5/10/20 秒窗口），
  线落进**绿色带**就是准，黄 = 偏一点，红 = 偏很多；下面还有一条实时**声波**（波形）线
- 你现在唱的是 **do / re / mi / fa / sol / la / xi** 里的哪一个，以及是第几组（八度）
- 这个音的**标准频率**是多少 Hz，你唱的实际频率是多少 Hz
- 你**偏高 / 偏低多少音分**（100 音分 = 1 个半音），用指针表实时显示
- 完整音阶的**标准频率对照表**，点一下就能听标准音
- **我的音域**设置：选自己的声部（预设 男低音 / 男中音 / 男高音 / 女低音 / 女中音 / 女高音 / 自定义），
  音域外的音会自动**变灰**并提示，不会让你硬唱上不去的高音
- 可以**录音**（只记音高、不存声音），自动统计"每个音平均偏高多少、稳不稳"，并**导出 JSON** 发给我做分析

> **隐私**：纯前端静态网页 —— 没有后端、没有统计脚本、不加载任何第三方资源。
> 你的麦克风声音、你选的本地音频，全部**只在浏览器内存里参与计算，不上传任何地方**；
> 网站作者也拿不到任何数据。选本地文件走的是浏览器文件选择器，只有你主动选的文件会被读取。

## 一、怎么用

1. 用 **Chrome / Edge / Safari** 打开网页（必须是 `https://` 或者 `localhost`，否则浏览器不给用麦克风）。
2. **先设音域**：右上角「我的音域」选自己的声部（我的选「男中音偏男高」，见第二节）。
   设好之后，音阶表里音域外的音会变灰，高音不再"骗"你去唱。
3. 点 **「开始收音」**，在弹窗里选"允许"。
4. 对着麦克风唱一个长音，比如 `la3——`，看两样东西：
   - **①下面的实时音高曲线**：线在绿色带里 = 准；往上飘 = 偏高。
   - **大字号唱名 + 指针**：指针在 **±25 音分**以内就是准的，往右 = 比标准音**高**。

### 针对"sol 容易太高、la 上不去"的练法

1. **把音区调到第 3 组**（do3 = 130.81 Hz，sol3 = 196.00，la3 = 220.00）。
   别再在 do4 起：do4–do5 那条音阶的 sol4 = 392、la4 = 440 已经顶到你的天花板了。
2. 在「标准频率表」里点 **▶ 听**，把 `sol3`、`la3` 的标准音各听 3 遍，先记住那个高度。
3. 慢慢唱 `sol3 → la3`，盯**实时曲线**：如果一到 sol 线就往上飘，说明你是**靠往上滑找音**，而不是直接落在音上。
4. 改成"先在心里想好高度，再出声"，出声后立刻看线有没有落进绿色带（±25 音分内）。
5. 反过来练：`do4 → xi3 → la3 → sol3`，从高往低唱比从低往高唱更容易找准，不容易越滑越高。
6. 用「单音跟唱测试」逐音测试，每个音重复 5 次，记录分数，看哪个音最难稳。

## 二、我的音域 = A2 ~ A4（110 ~ 440 Hz）

用音域测试测出来的是 **A2 到 A4，正好两个八度（24 个半音）**，属于**男中音偏男高音**那一类：

- 男中音（Baritone）常见音域约 **A2–F4**，男高音（Tenor）约 **C3–A4**；
  你下能到 A2、上能到 A4，是**偏低音区厚、但高音还能往上够**的类型 —— 典型的 Baritone with a lean toward Tenor。
- **关键结论**：`sol4 = 392 Hz` 已经贴着你 440 的天花板，`la4 = 440` 就是你极限。
  所以你原来按 do4 起的音阶往上唱，到 sol4/la4 当然"上不去"，那不是音准差，是**音阶起太高了**。
  练声改用 **do3 起**（do3 = 130.81 → do4 = 261.63），你的 sol3 = 196、la3 = 220 会轻松很多。

你的音域内每个音的频率：

| 唱名 | do | re | mi | fa | sol | la | xi |
|---|---|---|---|---|---|---|---|
| **第 2 组** | do2 65.41 ❌低于A2 | — | — | — | — | **la2 110.00** | xi2 123.47 |
| **第 3 组** | **do3 130.81** | re3 146.83 | mi3 164.81 | fa3 174.61 | **sol3 196.00** | **la3 220.00** | xi3 246.94 |
| **第 4 组** | do4 261.63 | re4 293.66 | mi4 329.63 | fa4 349.23 | sol4 392.00 | **la4 440.00** | xi4 493.88 ❌ |

（❌ = 超出你的音域。网页里的音阶表会自动把这些音标灰。）

以 **A4(la) = 440 Hz** 为准，十二平均律：

| 唱名 | 音名 | 频率 (Hz) |  | 唱名 | 音名 | 频率 (Hz) |
|---|---|---|---|---|---|---|
| do  | C4 | 261.63 | | sol | G4 | 392.00 |
| re  | D4 | 293.66 | | la  | A4 | 440.00 |
| mi  | E4 | 329.63 | | xi  | B4 | 493.88 |
| fa  | F4 | 349.23 | | do(高) | C5 | 523.25 |

其他八度：低一组（C3 ~ C4）是 `do=130.81, re=146.83, mi=164.81, fa=174.61, sol=196.00, la=220.00, xi=246.94`；
高一组（C5 ~ C6）是 `do=523.25, re=587.33, mi=659.26, fa=698.46, sol=783.99, la=880.00, xi=987.77`。
规律：**每升高一个八度，频率 ×2**；每升高一个半音，频率 ×2^(1/12)。

网页里的「标准音对照」可以切换组，直接看到任意八度的数字。

## 三、K歌练习页（karaoke.html）

主页面是「练音准」，K歌页是「练歌」。打开 `karaoke.html`（主页顶部有入口）。

**它是怎么打分的**：我在代码里写好每首歌的**音符序列**（唱名 + 拍数），
所以能精确算出「这首歌每个瞬间的标准音高」——也就是那条**灰蓝色阶梯线**；
你唱的实时叠在同一条时间轴上，逐音比对取中位数，得出偏差和分数。

**内置曲目**（全部是公有领域旋律 + 自编练习曲，不涉及版权音频）：

| 曲目 | 类型 | 音域（原调） | 对 A2–A4 的自动移调 |
|---|---|---|---|
| 音阶上下行（热身） | 自编练习 | C4–C5 | −12 → C3–C4 |
| 琶音跳进 do-mi-sol-do | 自编练习 | C4–D5 | −12 → C3–D4 |
| 小星星 Twinkle | 儿歌 | C4–A4 | 0（原调就合适） |
| 两只老虎 Frère Jacques | 民谣 | G3–A4 | 0 |
| 欢乐颂 Ode to Joy | 古典 | C4–G4 | 0 |
| Jingle Bells | 儿歌 | C4–G4 | 0 |
| 生日快乐 Happy Birthday | 民谣 | G4–G5 | −12 → G3–G4 |

**功能**：

- **自动适配我的音域**：读取主页①里设的 A2–A4，自动挑一个移调量（优先整八度，保住原调），
  让整首歌落进你的音域；也可以手动 ±半音
- **速度**：0.6x / 0.8x / 1.0x / 1.15x，慢练不丢人
- **本地音乐**：任意 mp3/flac 都能进来练，并自动估出旋律线当评分基准
- **歌词（.lrc）**：选音频时把同名的 `.lrc` 一起选上就会自动配对（按文件名匹配），
  播放/跟唱时同步高亮当前行。做了 UTF-8 / GBK 自动识别。已用真实曲库 200 个 `.lrc`（2282 行）验证解析。
- **引导旋律 + 节拍器**：浏览器实时合成（不下载任何音频），还有 4 拍起拍
- **实时提示**：现在该唱哪个音、你唱的是哪个音、偏差多少音分、**这个音的实时得分**
- **成绩单**：总分、平均偏差、命中率、整体偏高/偏低倾向、**最该练的那个音**，逐音表格带进度条
- **导出 JSON / CSV**：同时包含「歌的目标音高线」和「你的原始音高轨迹」
- **自由练习（④）· 直接用你自己的本地音乐**（网易云/QQ音乐下载的文件也行，只要是 mp3/m4a/wav/flac）：
  1. **从音频里估主旋律音高线**：解码 → **带通滤波（高通 120Hz 去贝斯/底鼓 + 低通 1200Hz 去镲片，
     同时当降采样抗混叠）** → 降采样到 ~11kHz → 每 46ms 一帧跑 YIN（**音高搜索范围限定在人声区**）
     → **简化版 Viterbi（动态规划）**把逐帧结果串成一条**连续的旋律线**
     （代价 = 偏离检测音高 + 换音"过路费"）→ 按最短音符切成「旋律片段」，
     片段音高取原始检测值的**中位数**，并且**要求至少 1/3 的帧真的检测到音高**才拿去打分。
     3~5 分钟的歌大约 2~5 秒算完（分块处理，不会卡死页面）。

     **为什么需要这些**：伴奏里贝斯/底鼓的周期性最强，不加限制的话 YIN 会一直锁在贝斯上
     （实测：周华健《难念的经》会提取出一整条 D#2/E2 的低音线，完全不是人声）。
     加了「人声滤波 + 限定人声范围」之后，同一首歌提取出来是 E3~A#4、中位数 G3，旋律呈级进上行，正确。
     界面上可以选**男声（E3–C5）/女声（G3–E5）/很宽（E2–E5）**，也可以关掉滤波（清唱/独奏录音时可能更好）。
  2. **从头同步跟唱（可打分）**：歌和录音一起开始，并用 `audio.currentTime` 持续校准时间轴，
     然后**用估出来的旋律线当评分基准**，给任意本地歌曲打分。
  3. **八度自动对齐**：男生低八度唱女声歌不会被判"差 1200 音分"，
     偏差会先折叠到 ±600 音分再评分，参考线也会按你的八度整体平移。
- **显示**：参考线画成**阶梯线**（同一个音横着走、换音处竖着跳），静音/间奏处才断开 ——
  所以看起来是连续的，而不是一堆碎点。其中
  **实线 = 这一段真的检测到了人声**，**细虚线 = 没测到、由算法推出来的估计值**（别把它当标准答案）。
  你唱的那条线也放宽了断点判定（700ms 内都连起来），断点处会画小圆点。
- ⚠️ 提取是**估计**：伴奏、鼓、和声、混响都会干扰。**人声突出 / 清唱 / 编曲简单的歌更准**。
  如果画出来的灰绿细线和这首歌的旋律不像（比如跟着贝斯跑了），那这个分就不算数，
  请改用「⏺ 只记录我的音高」把轨迹导出给我分析。
- ✅ **`.ncm` 已经能转了**：仓库里的 `tools/ncmdump.js` 可以直接把网易云 `.ncm` 还原成 mp3/flac
  （算法与密钥常量来自 MIT 许可的开源项目 [taurusxin/ncmdump](https://github.com/taurusxin/ncmdump)，
  许可证副本见 `tools/LICENSE-upstream-ncmdump.txt`；本仓库是其 JavaScript 重写版）：
  ```bash
  node tools/ncmdump.js "C:\CloudMusic\VipSongsDownload" -o "C:\CloudMusic\converted" --manifest
  ```
  算法对齐自活跃维护的项目 [taurusxin/ncmdump](https://github.com/taurusxin/ncmdump)（★4.6k）：
  AES-128-ECB 解出 RC4 密钥 → **无状态 256 字节周期密钥流**异或还原音频；
  元数据用第二把密钥（`sModifyKey`）解开，可以核对码率/时长/歌名。
  实测本机 1077 个 `.ncm`：**1077/1077 成功**，且 1077/1077 通过「码率 × 时长 ≈ 实际大小」校验，
  抽样用 `ffprobe` 复核码率/时长完全吻合。转换 9.7GB 用时 93 秒，并会输出 `ncm-manifest.json` 清单。
  仍需注意：网易云加密格式会随客户端更新，本工具按 fLaC/mp3 两种内层格式处理。

**打分规则**（写死可查，不搞玄学）：

- 每个目标音，取你在这段时间内音高的**中位数**（抗抖音、抗个别爆音）
- 偏差 = 你唱的实际音高 − 目标音高，单位音分（100 音分 = 1 个半音）
- 单音得分 = `100 − |偏差|×1.2`（0 音分 = 100 分，50 音分 = 40 分，83 音分以上 = 0 分）
- **漏唱 / 没声音 = 0 分**，所以漏唱会直接拉低总分
- 总分 = 所有目标音得分的平均

### 让「音高线」真正跟上人声：先做人声分离（推荐）

浏览器里那套 DSP（带通滤波 + 限定人声范围）只能**尽力避开**贝斯和鼓，伴奏一满还是会被带跑
（实测周华健《难念的经》：不处理时整条线会落在 D#2/E2 ≈ 78Hz 的贝斯上，完全不是人声）。

现在的标准做法是**先把人声分离出来，再提取音高** —— 这也是业界主流流程：
**UVR**（[ultimatevocalremovergui](https://github.com/Anjok07/ultimatevocalremovergui)，★26k，图形界面）、
**Demucs**（[facebookresearch/demucs](https://github.com/facebookresearch/demucs)，★10k）、
**BS-RoFormer/MDX23C**（UVR5/MSST 里更新的模型）、早期还有 **Spleeter**（★28k）。

仓库里给了一个基于 Demucs 的脚本：

```powershell
# 单首（会输出 难念的经.vocals.mp3 和 难念的经.no_vocals.mp3）
powershell -ExecutionPolicy Bypass -File tools\separate-vocals.ps1 -Path "C:\CloudMusic\周华健 - 难念的经.mp3"
# 整个目录
powershell -ExecutionPolicy Bypass -File tools\separate-vocals.ps1 -Path "C:\Music" -Out "C:\Music\vocals"
```

然后在 K歌页 ④ 里选 **`xxx.vocals.mp3`** 当音频 —— 音高线就会干净非常多
（纯人声时可以把「人声滤波」关掉，「人声范围」按原唱性别选）。
分离出的 `.no_vocals.mp3` 是伴奏，可以当自己的 K 歌伴奏用。

CPU 上大约 1~3 分钟/首（实测 4 分 48 秒的歌用了 226 秒）；有 NVIDIA 显卡会快很多。
首次运行会自动下载模型（约 80MB）。

**实测对比（周华健《难念的经》4:48，同一套提取算法）**

| 输入 | 真实检测率 | 提取音域中位 | 说明 |
|---|---|---|---|
| 原混音 · 不滤波不限范围 | 34% | **G2（98 Hz）** | 整条线是**贝斯线**，不是人声 |
| 原混音 · 人声滤波+限范围 | 25% | G3（196 Hz） | 靠 DSP 硬避，能救回大方向 |
| **Demucs 分离后的人声轨** | **51%** | **A3（220 Hz）**，音域 E3–C5 | 检测率翻倍，音符片段 96→302 个，声区与真人演唱一致 |

结论：**分离人声 = 质变**；只靠 DSP = 治标。想认真练一首歌，值得跑一次 Demucs。

**⚠️ 重要**：用音箱放引导旋律时，麦克风会把引导音也当成"你唱的"。
**要打分就戴耳机**；不戴耳机就取消勾选「播放引导旋律」，只留节拍器跟着唱。

## 四、部署到 GitHub Pages（免费）

### 方法 A：网页操作（不用命令行）

1. 打开 <https://github.com/new>，新建一个仓库，例如 `vocal-pitch-monitor`，选 **Public**，点 Create。
2. 进入仓库 → **Add file → Upload files**，把本文件夹里的 **`index.html`、`style.css`、`js/` 文件夹**（`js/pitch.js`、`js/app.js`）拖进去，点 **Commit changes**。
3. 仓库 → **Settings → Pages**，`Source` 选 **Deploy from a branch**，`Branch` 选 **main** 和 **/ (root)**，点 Save。
4. 等 1 分钟左右，刷新页面，会看到网址：`https://你的用户名.github.io/vocal-pitch-monitor/`。
5. 用手机或电脑打开这个网址（**https**，可以用麦克风），加到主屏幕/书签即可。

### 方法 B：命令行

```bash
cd 本文件夹
git init
git add .
git commit -m "vocal pitch monitor"
git branch -M main
git remote add origin https://github.com/你的用户名/vocal-pitch-monitor.git
git push -u origin main
```

推送完同样在 **Settings → Pages** 里把 Branch 设为 `main` / `/ (root)` 就行。
（也可以在仓库里加一个 GitHub Action 用 `actions/deploy-pages` 部署，效果一样。）

### 本地测试

直接双击 `index.html` 大多数情况下能打开，但浏览器在 `file://` 下可能不给麦克风权限。更稳的做法是起个本地服务器：

```bash
cd 本文件夹
python -m http.server 8000
# 然后浏览器打开 http://localhost:8000
```

## 五、把录音发给我做分析

1. 点「开始收音」→ 点「⏺ 开始录音」。
2. 按顺序唱：`do re mi fa sol la xi do`，**每个音唱 2~3 秒长音**，一共 30 秒左右。想让我看你唱得高的那几个音，就把 `sol`、`la` 多唱两遍。
3. 点「⏹ 停止录音」，然后点 **「导出 JSON」**，浏览器会下载一个 `pitch-日期-时间.json`。
4. 把这个文件发给我就行。

JSON 文件长这样（已经带好了汇总统计，不用你自己算）：

```json
{
  "app": "vocal-pitch-monitor",
  "a4": 440,
  "durationMs": 31240,
  "summary": {
    "avgAbs": 22.4,          // 全程平均偏差（音分，绝对值）
    "avgBias": 8.1,          // 全程平均偏差（带符号，正数=整体偏高）
    "in25": 41.2,            // 有多少比例落在 ±25 音分内
    "in50": 78.6,            // 有多少比例落在 ±50 音分内
    "nearEdge": 12.0,        // 有多少比例卡在两个半音正中间
    "worst": { "sol": "sol", "avg": 46.3 }
  },
  "perNote": [               // 逐音统计：哪个音偏高、稳不稳，一眼就能看出来
    { "solfege": "sol", "note": "G4", "seconds": 3.1, "frames": 44,
      "avgCents": 46.3, "avgAbsCents": 46.3, "sdCents": 12.4,
      "in50Percent": 55.0, "in25Percent": 2.1 }
  ],
  "points": [                // 原始音高轨迹，每 ~70ms 一个点
    { "t": 0, "f": 392.51, "midi": 67.02, "cents": 2.1, "note": "G4", "solfege": "sol4" }
  ]
}
```

有 `perNote` 和原始 `points` 这两层数据，我可以：
- 指出你哪个音是**系统性偏高/偏低**（比如 sol 平均 +46 音分，那就是真高了快半个音）
- 看你是**起点不准**还是**唱着唱着飘走**（`points` 里的走势）
- 看**稳定性**（`sdCents` 大就是抖）
- 对比前后两次录音，看有没有进步

也可以导出 **CSV**，用 Excel 自己画图。

## 七、技术说明

- **音高检测**：YIN 算法（自相关 + 累积均值归一化 + 抛物线插值），在 48kHz 采样下用 4096 点窗口，
  检测范围约 `C2(65Hz) ~ E6(1300Hz)`。纯正弦波实测误差 < 0.4 音分，加噪声后 < 2 音分。
- **实时曲线**：约 30fps 重绘、16fps 做音高分析；纵轴自动跟你的音高走（平滑跟随，不抖），
  每条横线是一个半音并标了唱名，绿色带 = ±25 音分（准音区）。声波是最近约 85ms 的波形。
- **取值策略**：每 ~60ms 分析一次，取最近 400ms 内的有效检测结果做**中位数 + 邻近平均**，
  避免偶尔的八度跳变和抖动让显示乱跳。
- **音名换算**：`f = A4 × 2^((n − 69) / 12)`，`n` 是 MIDI 音号（中央 C = 60 = do4）。
  偏差用音分表示：`cents = (实际MIDI − 最近整数MIDI) × 100`。
- **隐私**：没有后端、没有第三方脚本 CDN、没有任何网络请求，麦克风数据只在本机内存里处理。
- **K歌打分**：歌的音符序列 → 绝对时间轴（毫秒）→ 每个音的目标 MIDI；
  演唱轨迹按时间切片取中位数 → 音分偏差 → 分数。移调是给目标 MIDI 整体加偏移，
  所以「自动适配音域」不会影响打分的严谨性。
- **兼容性**：Chrome / Edge / Safari 最新版（需要 `getUserMedia` + `AudioContext`），
  手机端也能用（iOS Safari 需要 https）。

## 八、小提醒

- **仓库里不要提交任何音频**：`.gitignore` 已经挡掉 `*.mp3 / *.flac / *.wav / *.ncm / *.lrc / karaoke-*.json` 等。
  网站本身不需要任何音频文件，练歌时用浏览器本地选择即可。

- 唱的时候**别用抖音**，音高抖得厉害检测会跳来跳去。
- 环境和麦克风距离影响很大：安静房间 + 麦克风离嘴 15~25cm 最准。
- 用手机/电脑音箱播放参考音时，麦克风会把参考音也收进去，建议**戴耳机**。
- 一次只唱一个音，唱稳了再看指针，比一边滑一边看有用得多。
